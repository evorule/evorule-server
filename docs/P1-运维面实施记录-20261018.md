## W-1 全通道 WAL checkpoint 管理端点（464757d）

- `POST /api/admin/wal/checkpoint`：三通路（会话 / 单反应器 / 共享事实）
  各执行一次纯追加式分片切换，崩溃安全。
- partial failure 逐项上报不整体 fail，HTTP 恒 200；`rotated:false` =
  纯内存/无可轮换后端（非失败）。
- 人工治理动作：自动化凭据（service/app）拒绝 + 平台管理员硬校验；
  落账 `platform.event`（admin_wal_checkpoint）。
- 支撑改动：`SharedFactsLog` 补 `rotate_wal()` 委托原语（+2 单测）；
  governance patch 经 `[patch.crates-io]` 路径补丁对齐 vendored reactor。
- 测试：`admin_wal_checkpoint_admin_gated`（401/403/管理员执行三段）。

## W-5 启动期 WAL 全链校验（b26a2cd）

- CLI：`--verify-wal-on-start`（env `EVORULE_VERIFY_WAL_ON_START`），缺省
  false（opt-in，resolve 缺省值断言锁定）。
- 两通路校验（均复用既有原语，零 patch 改动）：
  - 反应器审计链：`Auditor::verify()` 全量重算哈希链（GovernanceApi 装配前、
    auditor move 前调用）；
  - 共享事实账本：`verify_causal_consistency()` 孤立 fact 检测（recover 成功
    分支内）。
- 失败语义：不拒启（取证保护现场）——warn 留痕 + health 告警位；flag 开但
  无 wal_dir 显式告警跳过。
- health 呈现：`wal.verify{reactor,shared_facts}`，取值
  `skipped`/`ok`/`failed`（静态 AtomicU8，main 启动期一次性写入）。

## W-4 磁盘满演练集成测试（1b8786a）

- 模拟手段经报批（方案 A，2026-10-18）：磁盘满在写路径的表现=持续写失败
  （同一错误分支：open/write Err → WalError → 连续计数）。复用仓内 W1 回归
  先例「目录冒充轮换目标」，零 patch 改动、跨平台、CI 可跑。
- 机制链演练：vendored patch 依赖解析下阈值=3 升级行为链锁定——连续计数
  递增 → 达阈值错误升级含自助诊断 → 升级回调恰好一次。
- 治理面演练：WAL-backed 共享事实通路轮换失败时 checkpoint 端点 partial
  failure 逐项上报（error 项 + HTTP 恒 200 + 其余通路不受牵连 + 故障后
  append 仍可用）。
- 夹具改动：`make_test_state_full` 增设 `shared_facts` 注入参数，既有调用方
  传 `SharedFactsLog::new()` 行为不变。

## 口径说明

1. **W-3 指标名为重建口径**：设计稿原文已失，指标名按实况重建如上；
   以代码与本文为准。
2. **W-4 模拟手段为报批后定谳**：设计稿候选 FailWriter 注入面经实测不存在；
   方案 A（OS 级目录注入）经批准实施，报批记录见对话留痕。
3. **W-3 遗留测试缺陷顺手修复（随 W-5 commit 留痕）**：`WalObservation` 的
   `WAL_OBSERVATION` 为进程级 OnceLock，原三个单测各自走 `register()`，
   并行调度下后到者拿到绑定他人 registry 的全局实例，产生顺序性假失败。
   修复：构建核心抽为不触全局的 `build()`，测试态一律独立实例；`register`
   的 OnceLock 语义改用顺序无关断言（返回值与 `global()` 恒同一）锁定。
